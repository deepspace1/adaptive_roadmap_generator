# Roadmap Generation — Presentation

## Objective
- Explain what the adaptive roadmap is, how it is generated, and why it matters.
- Show how the same topic produces different roadmaps for two users.
- Provide clear speaker notes for a 4-person team demo.

---

## 1 — What is the Roadmap?
- A sequenced, personalized learning plan for a learner and a goal.
- Composed of milestones → modules → lessons → assessments.
- Generated by a set of cooperating agents using structured specs and user data.

---

## 2 — Why it matters (one-liners)
- Personalizes learning to save time and improve mastery.
- Makes learning repeatable and explainable via specs.
- Enables continuous adaptation from performance data.

---

## 3 — Core components (roles)
- Planner: decomposes goals into milestones and schedules them.
- Teacher: creates lesson content and examples per learner level.
- Socratic coach: designs reflection questions to probe understanding.
- Quiz & evaluator: creates assessments and scores mastery.
- Knowledge-gap detector: finds missing prerequisites and recommends remediation.
- Memory store: saves progress, preferences, and recent interactions.
- Dashboard/Analytics: surfaces progress and recommendations.

---

## 4 — Inputs and Outputs
- Inputs:
  - `specs/` (learning objectives, module templates)
  - learner profile (background, goals, constraints)
  - prior assessments and interaction history
- Outputs:
  - ordered roadmap (milestones + modules + suggested schedule)
  - recommended assessments and resources

---

## 5 — Generation flow (short step-by-step)
1. Intake: read learner profile + selected goal.
2. Planner: map goal → milestones using `specs/` rules.
3. Module synthesis: for each milestone, generate modules and learning items.
4. Prompt-driven content: Teacher and Coach generate content via prompt templates.
5. Assessment design: Quiz agent creates evaluative items per module.
6. Scoring & adapt: evaluator runs after assessment; Knowledge-gap detector updates roadmap.
7. Persist: memory store logs progress and preferences for future runs.

---

## 6 — Prompting strategy (how prompts are structured)
- Use a small set of templates: `system`, `task`, and `example` blocks.
- Inject variables: learner level, time-per-week, constraints, target mastery.
- Provide short examples (few-shot) for desired output shape (JSON/YAML list).
- Keep models deterministic for reproducibility (low temperature, fixed seed).
- Validate outputs against `schemas` before applying (reject/repair malformed responses).

---

## 7 — Two-user example (same topic: "Intro to Python")

### User A — Novice (Student)
- Profile: no programming background, 4 hours/week, goal: basic scripting and data analysis.
- Planner output (high-level):
  1. Milestone 1: Essentials — Syntax, variables, control flow
     - Module: Python syntax & REPL practice
     - Assessment: short coding exercises
  2. Milestone 2: Data structures & I/O
     - Module: lists, dicts, file I/O
  3. Milestone 3: Intro to libraries
     - Module: numpy basics, pandas intro
  4. Milestone 4: Mini project
     - Module: build a small data-cleaning script
- Schedule: spaced practice with weekly quizzes and remediation after low scores.

### User B — Experienced (Analyst)
- Profile: comfortable with Excel, wants automation & data pipelines, 6 hours/week.
- Planner output (high-level):
  1. Milestone 1: Python for automation
     - Module: scripting, file manipulation, subprocess
  2. Milestone 2: Data pipelines
     - Module: pandas advanced, csv/json handling, I/O performance
  3. Milestone 3: Testing & tooling
     - Module: unit tests, virtualenv, packaging
  4. Milestone 4: Applied project
     - Module: automate a real-world data workflow
- Notes: fewer basics, faster progression, more project-based assessments.

---

## 8 — How adaptation is triggered
- Post-quiz scores below mastery → insert remediation modules or change schedule.
- Repeated errors on a concept → split module into smaller steps.
- Learner time constraints change → re-schedule milestones.

---

## 9 — Evaluation & success metrics
- Mastery rate per milestone (target %).
- Time-to-mastery (weeks to reach threshold).
- Retention (repeat assessment after interval).
- Engagement (completion rate of modules & quizzes).

---

## Appendix — Quick Breakdown (to include in demo)

What is the roadmap generator
- A programmatic pipeline that creates a personalized learning plan (roadmap) for a learner and a chosen goal.
- Output: ordered milestones → modules → lessons → assessments + schedule and resources (JSON/YAML).

Steps — what happens
1. Intake: receive learner profile + goal + constraints + prior history.
2. Normalize: map inputs to canonical spec entries and infer start level.
3. Planner: decompose goal into milestones and rough pacing.
4. Module synthesis: create modules & lesson slots for each milestone.
5. Content generation: Teacher + Coach produce lesson text, examples, Socratic questions via prompts.
6. Assessment creation: Quiz agent generates questions, rubrics, passing thresholds.
7. Validate & persist: validate against schemas, store roadmap + checkpoints in DB.
8. Adaptation loop: after assessments, evaluator + knowledge-gap detector update roadmap (remediation, reschedule, split).

What it asks (inputs)
- Required: `goal` (topic id), `learner_profile` (background, level, hours/week, preferences).
- Optional: prior quiz scores, specific constraints (time, tool access), content tone.
- System-level: `max_milestones`, `mastery_threshold`, `output_format` (JSON/YAML).

How it works (internals, plain)
- Specs drive structure: `specs/` tells the planner how to split goals into milestones/modules.
- Agents are components: Planner (structure), Teacher (content), Coach (questions), Quiz/Evaluator (assessments & scoring), Knowledge-gap Detector (remediation), Memory (persist state).
- Prompt templates instruct the content-generation agent to return a fixed schema; validator enforces shape and repair/re-run handles malformed outputs.
- Adaptation rules transform evaluator signals into roadmap edits (insert, split, reorder).

Tech specs (concise)
- Data model keys: `roadmap.id`, `milestones[]` → `modules[]` with `id`, `title`, `prereqs[]`, `objectives[]`, `estimate_hours`, `assessments[]`.
- Formats: JSON or YAML machine-readable outputs.
- APIs: `POST /generate-roadmap` (learner + goal → roadmap JSON), `POST /submit-assessment` (results → updated roadmap).
- Storage: persistent DB for roadmaps, scores, preferences.
- Validation: schema checks and repair heuristics; determinism via low temperature and caching.

Prompting methods (short)
- Template layers: `system` (constraints + output shape), `task` (what to produce), `example` (few-shot sample).
- Inject variables: `learner_level`, `time_per_week`, `goal_id`, `previous_failures`.
- Output control: require strict JSON/YAML structure and include a `status` field.
- Few-shot: include 1–2 examples showing desired JSON shape.
- Stability: use low temperature, consistent examples, and validate/retry on schema failure.
